Got it — that “Authorized” toast followed by an auto-logout and jump back to the login page is almost always a **session propagation** issue: the backend is issuing a token (or says it did), but the browser doesn’t keep it (cookie flags/CORS mismatch) or the frontend isn’t sending it back on the next request to `/api/auth/me`. Then your route guard sees a 401 and bounces you to `/login`.

Here’s a tight, copy-paste fix that makes login stick on Replit and unblocks the portal. It covers:

* Correct CORS + cookie settings for Replit (cross-site preview)
* Secure, httpOnly JWT cookie
* Middleware to read/verify the cookie
* Working `/api/auth/login`, `/api/auth/logout`, and `/api/session/me`
* Frontend fetch with `credentials: 'include'` so the cookie is actually sent

---

# 1) Server: CORS, cookies, JWT

**Install (if missing):**

```bash
npm i cors cookie-parser jsonwebtoken
```

**`server/index.ts` (top-level app setup):**

```ts
import express from 'express';
import cors from 'cors';
import cookieParser from 'cookie-parser';

const app = express();

const FRONTEND_URL = process.env.FRONTEND_URL
  // Replit preview can bounce; during dev allow the requesting origin
  ?? ''; 

app.use(express.json());
app.use(cookieParser());

app.use(
  cors({
    origin: (origin, cb) => {
      // In Replit preview, origin can change (e.g. *.repl.co, *.replit.dev)
      // Allow undefined (curl) and any https origin in dev; tighten in prod.
      if (!origin) return cb(null, true);
      if (/^https:\/\/.*repl(?!$)/.test(origin) || /^https:\/\/.*replit\.dev$/.test(origin)) {
        return cb(null, true);
      }
      if (FRONTEND_URL && origin === FRONTEND_URL) return cb(null, true);
      return cb(null, false);
    },
    credentials: true,
  })
);

// …your other middleware (logging, rate-limit, etc.)

import routes from './routes'; // ensure this is default export (Option A)
app.use('/api', routes);

const port = process.env.PORT || 5000;
app.listen(port, () => {
  console.log(`VictorySync running on :${port}`);
});
```

**`server/routes/session.ts` (auth middleware + me/logout):**

```ts
import { Router, Request, Response, NextFunction } from 'express';
import jwt from 'jsonwebtoken';

export const sessionRouter = Router();

type JWTPayload = { sub: number | string; orgId?: number | string; role?: string; };

const JWT_SECRET = process.env.JWT_SECRET || 'dev-secret-change-me';

// Shared cookie options
const baseCookieOptions = {
  httpOnly: true,
  // Replit preview is cross-site → SameSite=None + Secure=true required
  sameSite: 'none' as const,
  secure: true,
  path: '/',          // send to all paths
  // domain: undefined // usually omit on Replit so the browser accepts it
};

export function authRequired(req: Request, res: Response, next: NextFunction) {
  try {
    // Read from cookie first
    const token = req.cookies?.vs_session
      // or Authorization: Bearer <token>
      ?? (req.get('authorization')?.split(' ')[1] ?? '');

    if (!token) return res.status(401).json({ error: 'Missing token' });

    const decoded = jwt.verify(token, JWT_SECRET) as JWTPayload;
    // attach to req for downstream handlers
    (req as any).user = decoded;
    return next();
  } catch {
    return res.status(401).json({ error: 'Invalid token' });
  }
}

sessionRouter.get('/me', authRequired, async (req, res) => {
  // You can hydrate from DB here if you want; keeping it simple:
  return res.json({ user: (req as any).user });
});

sessionRouter.post('/logout', (req, res) => {
  res.clearCookie('vs_session', baseCookieOptions);
  return res.json({ ok: true });
});

export { baseCookieOptions, JWT_SECRET };
```

**`server/routes/auth.ts` (login issues cookie):**

```ts
import { Router } from 'express';
import jwt from 'jsonwebtoken';
import { baseCookieOptions, JWT_SECRET } from './session';
// import your db client here
// import { sql } from '../db'; // example

export const authRouter = Router();

authRouter.post('/login', async (req, res) => {
  const { email, password } = req.body as { email: string; password: string };

  // 1) Look up user and verify password (replace with your real code)
  // const user = await sql`select * from public_users where email=${email}`;
  // const ok = await bcrypt.compare(password, user.password_hash)
  const isDemo =
    email && password &&
    ((email === 'demo@victorysync.com' && password === 'VictoryScale123!') ||
     (email === 'admin@victorysync.com' && password === 'VictoryScale123!'));

  if (!isDemo) {
    return res.status(401).json({ error: 'Invalid credentials' });
  }

  // 2) Build token payload (replace ids/role with real data)
  const payload = {
    sub: 4,            // user id
    orgId: 'demo-scale',
    role: 'super_admin'
  };

  const token = jwt.sign(payload, JWT_SECRET, { expiresIn: '7d' });

  // 3) Set secure httpOnly cookie
  res.cookie('vs_session', token, {
    ...baseCookieOptions,
    maxAge: 7 * 24 * 60 * 60 * 1000
  });

  // 4) Also return JSON so client can react
  return res.json({ ok: true });
});
```

# 2) Frontend: include credentials, route guard

Wherever you call the API (login + me), you **must** send credentials or the cookie won’t ride along.

**`client/src/lib/api.ts` (optional helper):**

```ts
export async function api<T = any>(path: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`/api${path}`, {
    credentials: 'include',               // IMPORTANT
    headers: { 'Content-Type': 'application/json' },
    ...init,
  });
  if (!res.ok) throw new Error(await res.text());
  return res.json();
}
```

**Login page (`client/src/pages/login.tsx`)**

```tsx
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { api } from '../lib/api';
import { useNavigate } from 'react-router-dom';

export default function Login() {
  const qc = useQueryClient();
  const navigate = useNavigate();

  const login = useMutation({
    mutationFn: async (form: { email: string; password: string }) =>
      api('/auth/login', { method: 'POST', body: JSON.stringify(form) }),
    onSuccess: async () => {
      await qc.invalidateQueries({ queryKey: ['/api/auth/me'] });
      navigate('/customer-dashboard'); // or your portal path
    },
  });

  // … your form UI
}
```

**“Me” query used in a PrivateRoute / layout guard**

```tsx
import { useQuery } from '@tanstack/react-query';
import { api } from '../lib/api';
import { Navigate, Outlet } from 'react-router-dom';

function useMe() {
  return useQuery({
    queryKey: ['/api/auth/me'],
    queryFn: () => api('/session/me'),
    // avoid the "Query data cannot be undefined" warning:
    select: (d) => d?.user ?? null,
    retry: false,
  });
}

export function Private() {
  const { data: user, isLoading, isError } = useMe();

  if (isLoading) return null; // or spinner
  if (isError || !user) return <Navigate to="/login" replace />;

  return <Outlet />;
}
```

Ensure your router uses `<Private />` for the portal routes.

# 3) Environment you must set (Replit → Secrets)

* `JWT_SECRET` — any long random string
* (Optional) `FRONTEND_URL` — if you have a stable domain

> On Replit, preview is cross-site — **cookies won’t work** unless `SameSite=None; Secure` and `credentials:true` are set on both server & client. That’s the #1 reason you were “Authorized” then immediately “Unauthorized.”

# 4) Quick verification

1. Open devtools → Network → login request:

   * Response should include `Set-Cookie: vs_session=…; HttpOnly; Secure; SameSite=None`
2. Then hit:

   ```bash
   curl -i -X POST https://<your-host>/api/auth/login \
     -H 'Content-Type: application/json' \
     -d '{"email":"demo@victorysync.com","password":"VictoryScale123!"}' -c cookies.txt

   curl -i https://<your-host>/api/session/me -b cookies.txt
   ```

   The second call should be **200** with `{ user: … }`.
3. The app should stay on `/customer-dashboard` (or your portal) and render.

# 5) About “all features fully integrated”

Login/session is the gate for everything else (plans, billing, IVR, entitlements, etc.). Once the session sticks:

* Your `/api/session/me` should return the user’s `orgId` and `role`; use that to **hydrate entitlements** on the client (or return them directly from the server).
* If you need a **demo superuser** with all Scale plan features, the quick path is to:

  * Keep the hardcoded demo login (above)
  * Return `role: 'super_admin'` and an `entitlements` array from `/api/session/me` (or a `/api/entitlements` endpoint) that your UI/feature flags use.
* If your DB is ready, swap the hardcoded block in `/auth/login` for a real lookup + bcrypt, but keep the same cookie logic.
