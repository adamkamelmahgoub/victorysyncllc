Got it — you want the **original front-end (the SPA)** to show at the root like your **live deployed site**, not the temporary static page.

You’ve got two clean ways to do this. Pick A (best) if your `client/` code is present and builds; pick B (fast fallback) if you just want to mirror the live site right now.

---

# A) Serve your built SPA from `client/dist` (best / production-like)

Your server code is already set to **prefer `client/dist/index.html`** when it exists. So the fix is:

## 1) Fix the client TypeScript config issue (the error you saw)

That `TS5069: tsBuildInfoFile cannot be specified without 'incremental' or 'composite'` comes from `client/tsconfig.node.json`.

Edit **`client/tsconfig.node.json`**:

* EITHER remove the `tsBuildInfoFile` line
* OR add `"composite": true`

Example (safe choice — remove the build info line):

```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    // REMOVE this if it exists:
    // "tsBuildInfoFile": "./node_modules/.tmp/tsconfig.node.tsbuildinfo",
    "composite": true,          // <-- add this if you keep a build info file
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "types": ["node"]
  },
  "include": ["vite.config.ts"]
}
```

Also make sure **`client/tsconfig.json`** is sane for Vite/React (typical):

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "useDefineForClassFields": true,
    "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "skipLibCheck": true,
    "moduleResolution": "Bundler",
    "resolveJsonModule": true,
    "isolatedModules": true,
    "noEmit": true,
    "jsx": "react-jsx"
  },
  "include": ["src"]
}
```

## 2) Install and build the client

```bash
npm --prefix client install
npm --prefix client run build
```

That should produce **`client/dist/index.html`**.

> If you get an esbuild stack trace (red lines with `esbuild/lib/main.js`), it’s usually a missing peer dependency or an import path issue. Run `npm --prefix client i` once more, then re-run `npm --prefix client run build`. If it still errors, the exact message will point to the offending import/file.

## 3) Restart your server

Stop and run again. In the console you should now see:

```
[web] Serving built SPA from /home/runner/workspace/client/dist
```

And the root URL will render your “real” front end exactly like production.

> Note: You can keep `public/index.html` around; your server prefers `client/dist` when it exists.

# B) Quick win: proxy to your live site (fastest)

If you want it **right now** with zero client build, proxy all non-`/api` requests to the live production URL. This makes local behave *exactly* like your deployed site while keeping your API intact.

## 1) Install the proxy helper

```bash
npm i http-proxy-middleware
```

## 2) Update your static hosting block in `server/index.ts`

Keep your existing “dist or public” logic. **Add this proxy branch below it**, so if neither `client/dist` nor `public/index.html` exists, we proxy to production:

```ts
import { createProxyMiddleware } from "http-proxy-middleware";

// ... your existing static hosting code ...

} else if (process.env.FRONTEND_URL) {
  // Proxy all non-API traffic to the live site
  console.log(`[web] Proxying UI to ${process.env.FRONTEND_URL}`);
  const siteProxy = createProxyMiddleware({
    target: process.env.FRONTEND_URL,
    changeOrigin: true,
    secure: true
  });
  app.use((req, res, next) => (req.path.startsWith("/api") ? next() : siteProxy(req, res, next)));
} else {
  // Fallback (API-only notice)
  app.get("/", (_req, res) => {
    res
      .status(200)
      .send(
        `VictorySync API is running.<br/>` +
          `No UI found. Add <code>public/index.html</code> or build SPA to <code>client/dist</code>, ` +
          `or set <code>FRONTEND_URL</code> to your live site.`
      );
  });
}
```

## 3) Set the env var to your live site

In Replit secrets, add:

```
FRONTEND_URL=https://victorysync.com
```

Restart. Now the root of your Replit app shows the **live site**, while `/api/...` still hits your local API.

---

## Which should you pick?

* **A (build from `client/dist`)** → best match to production hosting; works offline; your code serves itself.
* **B (proxy)** → instant parity with live UI even if your local `client/` is incomplete or failing to build.

If you want, we can do both: keep the proxy as a safety net, and the moment `client/dist` exists, your current static code will automatically serve the built app instead of proxying.
