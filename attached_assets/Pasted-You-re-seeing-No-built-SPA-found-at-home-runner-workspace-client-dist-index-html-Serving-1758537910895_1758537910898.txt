You’re seeing:

```
No built SPA found at /home/runner/workspace/client/dist/index.html.
Serving API only. FRONTEND_URL=http://localhost:5173
```

That’s not a crash — it means the server can’t find a **built frontend** at `client/dist/index.html`. Fix it by creating the `client/` app and building it (or add a fallback HTML). Here are two fast paths — pick one.

---

## A) Proper fix: create the client app and build it

**Run these in the Replit shell from the repo root:**

```bash
# 1) Create a fresh Vite React+TS app
rm -rf client
npm create vite@latest client -- --template react-ts

# 2) Install its deps
npm --prefix client i

# 3) (optional but recommended) Add a dev proxy so /api talks to :5000 during dev
cat > client/vite.config.ts <<'EOF'
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  server: {
    port: 5173,
    proxy: {
      '/api': { target: 'http://localhost:5000', changeOrigin: true },
    },
  },
  build: { outDir: 'dist' },
})
EOF

# 4) Build the SPA (this creates client/dist/index.html)
npm --prefix client run build
```

**Then restart the server** (stop/run).
Now `client/dist/index.html` exists, so the root webview will serve the SPA instead of “API only”.

> Tip: while developing UI, run both in dev:
>
> ```bash
> npm run dev
> ```
>
> and open the `http://localhost:5173` preview (the Vite dev server). The API keeps running on `:5000`.

---

## B) Quick unblock fallback (serve a plain HTML if dist is missing)

If you just want something to render immediately without building:

1. **Create a public fallback file**

```bash
mkdir -p public
cat > public/index.html <<'EOF'
<!doctype html>
<html>
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width,initial-scale=1" />
    <title>VictorySync</title>
  </head>
  <body style="font-family: system-ui; padding: 24px;">
    <h1>VictorySync</h1>
    <p>Fallback UI. Frontend build not found yet.</p>
  </body>
</html>
EOF
```

2. **Update the server to use this fallback when `client/dist` is missing.**
   Replace your `server/index.ts` bottom section with this “3-tier” serve logic:

```ts
import express from 'express'
import cookieParser from 'cookie-parser'
import path from 'node:path'
import fs from 'node:fs'

const app = express()
const PORT = Number(process.env.PORT || 5000)
const FRONTEND_URL = process.env.FRONTEND_URL || 'http://localhost:5173'

const CLIENT_DIST = path.resolve(process.cwd(), 'client', 'dist')
const DIST_INDEX = path.join(CLIENT_DIST, 'index.html')

const PUBLIC_DIR = path.resolve(process.cwd(), 'public')
const PUBLIC_INDEX = path.join(PUBLIC_DIR, 'index.html')

app.use(express.json())
app.use(cookieParser())

import apiRoutes from './routes/index'
app.use('/api', apiRoutes)

// Static mounts (only if present)
if (fs.existsSync(CLIENT_DIST)) app.use(express.static(CLIENT_DIST))
if (fs.existsSync(PUBLIC_DIR)) app.use(express.static(PUBLIC_DIR))

app.get('*', (_req, res) => {
  if (fs.existsSync(DIST_INDEX)) {
    return res.sendFile(DIST_INDEX)
  }
  if (fs.existsSync(PUBLIC_INDEX)) {
    return res.sendFile(PUBLIC_INDEX)
  }
  res
    .status(200)
    .type('html')
    .send(
      `VictorySync API is running.<br/>Build the frontend (client/dist) to serve the SPA.<br/>Dev frontend at <a href="${FRONTEND_URL}">${FRONTEND_URL}</a>.`
    )
})

app.listen(PORT, () => {
  console.log(
    fs.existsSync(DIST_INDEX)
      ? `Serving built SPA from ${DIST_INDEX}`
      : `No built SPA found at ${DIST_INDEX}. Serving API only (fallback enabled). FRONTEND_URL=${FRONTEND_URL}`
  )
  console.log(`VictorySync API running on :${PORT}`)
})
```

**Restart**. You’ll now at least see the fallback HTML until you run the proper build in section A.

---

## Why this happened

* The server is correctly coded to serve a built SPA **if** `client/dist/index.html` exists.
* Because there’s **no build yet**, it logs “Serving API only” and you get the text page.

Once you run **A.3 build** (or add the fallback in **B**), that log will go away and you’ll see a real page.

If anything still complains after you build, run:

```bash
ls -la client/dist
```

and ensure `index.html` is there; then stop/start the server.
