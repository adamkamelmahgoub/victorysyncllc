# Explanation

You now have **integer** `organizations.id`, but some runtime value (very likely the org id coming from the JWT/session or a request param) is still a **string**. When your queries do `... WHERE e.org_id = ${orgId}` the driver binds `${orgId}` as `text`, so Postgres compares `integer = text` and throws.

We’ll fix this on **both layers**:

1. **DB hardening** so every org id surface has an **int** (plus an optional generated text column for any legacy queries you forget).
2. **Code hardening** so every org id you pass to SQL is **parsed to an integer** before binding, and every JWT/session stores it as a **number**.

Do both and the error is gone for good.

---

# Code

## A) One-time DB hardening (run in Neon SQL console)

This makes things tolerant and fast, even if a rogue string sneaks in later.

```sql
BEGIN;

-- Make sure entitlements has what the app expects
ALTER TABLE entitlements
  ADD COLUMN IF NOT EXISTS value TEXT;

-- Foreign keys (keeps types aligned and prevents drift)
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM information_schema.table_constraints
    WHERE table_name='users' AND constraint_name='users_org_fk'
  ) THEN
    ALTER TABLE users
      ADD CONSTRAINT users_org_fk
      FOREIGN KEY (org_id) REFERENCES organizations(id)
      ON DELETE SET NULL;
  END IF;

  IF NOT EXISTS (
    SELECT 1 FROM information_schema.table_constraints
    WHERE table_name='entitlements' AND constraint_name='entitlements_org_fk'
  ) THEN
    ALTER TABLE entitlements
      ADD CONSTRAINT entitlements_org_fk
      FOREIGN KEY (org_id) REFERENCES organizations(id)
      ON DELETE CASCADE;
  END IF;
END $$;

-- Belts & suspenders: generated text mirrors for debugging / legacy filters
ALTER TABLE organizations
  ADD COLUMN IF NOT EXISTS id_text TEXT
  GENERATED ALWAYS AS (id::text) STORED;

ALTER TABLE entitlements
  ADD COLUMN IF NOT EXISTS org_id_text TEXT
  GENERATED ALWAYS AS (org_id::text) STORED;

CREATE INDEX IF NOT EXISTS organizations_id_text_idx ON organizations(id_text);
CREATE INDEX IF NOT EXISTS entitlements_org_id_text_idx ON entitlements(org_id_text);

COMMIT;
```

> You won’t need the `*_text` columns once code is clean, but they make the system resilient and easy to inspect.

## B) Code hardening (Node/Express + neon)

Create a tiny helper and use it **every time** you pass an org id to SQL or encode it in JWT.

### 1) `server/db/id.ts`

```ts
// server/db/id.ts
export function toIntId(value: unknown, field = "id"): number {
  const n = Number(String(value ?? "").trim());
  if (!Number.isInteger(n) || n <= 0) {
    throw new Error(`Invalid ${field}: "${value}"`);
  }
  return n;
}
```

### 2) Fix your login route (`server/routes/auth.ts`)

Find the section that builds the JWT and fetches entitlements. Replace it with this pattern:

```ts
import { toIntId } from "../db/id";
import jwt from "jsonwebtoken";
import { sql } from "../db/client"; // however you import neon

// ... inside your login handler after verifying email/password:

// get/create the org and ensure it's an integer
const orgIdInt = toIntId(user.org_id ?? org?.id ?? req.body?.org_id, "org_id");

// Always store number in JWT
const token = jwt.sign(
  { uid: user.id, orgId: orgIdInt }, // <-- number, not string
  process.env.JWT_SECRET!,
  { expiresIn: "7d" }
);

// When querying, always bind integers
const entitlements = await sql/*sql*/`
  SELECT f.code, e.enabled, e.value
  FROM entitlements e
  JOIN features f ON f.id = e.feature_id
  WHERE e.org_id = ${orgIdInt}
  ORDER BY f.code
`;
```

### 3) Fix your auth middleware (JWT decode path)

Where you read the JWT and load data, normalize early:

```ts
import { toIntId } from "../db/id";

// after decoding token:
const orgId = toIntId((payload as any).orgId, "orgId");

// any queries:
await sql/*sql*/`SELECT ... FROM organizations WHERE id = ${orgId}`;
await sql/*sql*/`SELECT ... FROM entitlements WHERE org_id = ${orgId}`;
```

# Why this is “for good”

* All **DB relations** are aligned on integer ids and protected with **FKs**.
* Your app **never** binds a string where an integer is expected.
* JWT/session always carry **numeric** `orgId`.
* Optional generated text columns give you a painless escape hatch if any legacy query slips in, but your main path stays strictly typed.
