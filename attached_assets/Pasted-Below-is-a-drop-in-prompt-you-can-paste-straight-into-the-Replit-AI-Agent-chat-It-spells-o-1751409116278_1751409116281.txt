#### Detailed Fix List

1. **Front-end routing**

   * Add **`src/app/login/page.tsx`** and `src/app/signup/page.tsx` (or Next.js `/pages/login.tsx` & `/pages/signup.tsx` if you’re on Pages Router) that import the existing AuthForm component.
   * Replace any nav link that points to `/api/login` with `/login`.

2. **API route / handler**

   * Ensure **POST `/api/auth/login`** and **POST `/api/auth/register`** exist and are exported in production build.
   * If using Next.js API routes, verify the files land in `build/` (TypeScript compiled).

3. **Passport strategy bootstrap**

   * In `server/auth/passport.ts` (or equivalent) **import and `passport.use()` the three providers *before* route definitions**:

     ```ts
     passport.use('google', new GoogleStrategy({...}));
     passport.use('facebook', new FacebookStrategy({...}));
     passport.use('apple', new AppleStrategy({...}));
     ```
   * Export `initializePassport()` and call it in `server/index.ts` **before** `app.use(routes)`.

4. **Environment variables & runtime checks**

   * Update **`.env.example`** with:

     ```
     JWT_SECRET=
     GOOGLE_CLIENT_ID=
     GOOGLE_CLIENT_SECRET=
     FACEBOOK_APP_ID=
     FACEBOOK_APP_SECRET=
     APPLE_CLIENT_ID=
     APPLE_TEAM_ID=
     APPLE_KEY_ID=
     APPLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----"
     ```
   * Modify each provider strategy so if any required ENV var is missing it throws at **server start** (clear stack-trace) instead of returning “not configured” at request time.

5. **Callback routes**

   * Ensure routes match strategy names exactly:

     ```
     GET /api/auth/google
     GET /api/auth/google/callback
     ...
     ```
   * After successful passport auth, generate JWT with `createJwt(user)` and redirect to `/dashboard?token=<jwt>`.

6. **Build / run scripts**

   * `package.json` should have

     ```json
     "build": "tsc -p tsconfig.json",
     "start": "node build/index.js"
     ```

     (or `tsup`/`esbuild` if preferred).
   * Remove `tsx` from the production `start` script.

7. **Automated smoke tests**

   * Inside `scripts/testAuth.mjs` add a tiny fetch test that:

     * Registers a temp user → expects 201
     * Logs in → expects 200 + token
     * Calls `/api/auth/me` with token → expects 200
   * Run this script in `npm run build && npm run testAuth` to verify prod build before deploy.

8. **README note**: Add “## Configure OAuth” with links to Dev console setup and required redirect URIs (`https://<domain>/api/auth/<provider>/callback`).
